You are a senior full-stack engineer implementing an AI Governance Control Plane inside Client Vault.

Non-negotiables

Governance is enforced server-side (middleware), never “UI-only”.

Every AI action is attributable (actor_id + persona_id).

No overwrites: governance artifacts and AI events are append-only + versioned.

Policy evaluation must support Global → Client Override → Project Override → Artifact Override, where more restrictive wins.

When blocked, API returns a structured error: GOVERNANCE_DENIED with reasons + required escalation.

UI must reflect gating in real time using a GET /api/governance/effective endpoint and disable actions + show tooltips.

Tech assumptions

Node/Express backend.

Postgres (or Supabase) for persistence.

Frontend in React (Vite/Next ok). Use existing auth patterns.

There is an existing concept of client, project, artifact/document, timeline/events.

If any of these differ, still implement with minimal adaptation and keep the same contracts.

1.2 Governance policy JSON schema

Implement and validate a JSON schema (zod or ajv). Policy object:

{
  "policyVersion": "1.0",
  "aiAllowed": true,
  "standing": { "client": "ACTIVE|RESTRICTED|TERMINATED|DISPUTED" },

  "classificationRules": {
    "defaultClassification": "CLIENT_PRIVATE",
    "artifactOverrides": {
      "ATTORNEY_PRIVILEGED": { "aiRead": false, "aiWrite": false },
      "RESTRICTED": { "aiRead": false, "aiWrite": false }
    }
  },

  "personas": {
    "allowList": ["DDIE","VAULT_SUMMARIZER"],
    "denyList": []
  },

  "capabilities": {
    "AI_SUMMARIZE": { "allow": true, "requiresSupervisor": false },
    "AI_REWRITE": { "allow": true, "requiresSupervisor": true },
    "AI_LEGAL_DRAFT": { "allow": false, "requiresSupervisor": true },
    "AI_EXPORT": { "allow": false, "requiresSupervisor": true }
  },

  "scopeGuards": {
    "crossClientAccess": false,
    "crossProjectAccess": false
  },

  "escalation": {
    "supervisorRequiredFor": ["AI_REWRITE","AI_EXPORT","AI_LEGAL_DRAFT"],
    "supervisorRoles": ["ADMIN","SUPERVISOR"]
  }
}


Rules:

More restrictive wins when merging.

Missing action types default to deny.

If aiAllowed=false at any scope, deny all AI actions at that scope.

2) Enforcement Middleware (Express)
2.1 Middleware contract

Create middleware:
server/middleware/enforceGovernance.ts

It should:

Resolve context: client_id, project_id, artifact_id from params/body.

Resolve actor: actor_id from auth; actor_type default HUMAN unless route indicates AI.

Resolve persona: from header x-persona-key OR body personaKey.

Resolve action_type: map route to action type (central map).

Load policies: global + client + project + artifact (published only).

Merge policies → effective.

Evaluate action with evaluator.

Write an ai_actions_log row ALWAYS (ALLOW or DENY) with hashes.

If denied:

return 403 with:

{
  "error": "GOVERNANCE_DENIED",
  "actionType": "AI_REWRITE",
  "requiresSupervisor": true,
  "reasons": [
    { "code": "CAPABILITY_DENIED", "message": "AI_EXPORT is disabled at CLIENT scope", "scope": "CLIENT" }
  ],
  "nextSteps": ["REQUEST_SUPERVISOR_APPROVAL"]
}


If allowed but requiresSupervisor:

if no supervisor approval token present, return 403 same structure but with code SUPERVISOR_REQUIRED

if approval exists (stub acceptance), proceed.
